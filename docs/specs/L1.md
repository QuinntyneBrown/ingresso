# L1 - High-Level Requirements

## L1-001: Tile management
The system shall let a signed-in user create, view, edit and delete app tiles. A tile has a name, web address, description, colour and category.

## L1-002: Dashboard
The system shall show all of the user's apps as tiles on one dashboard. Recently opened apps get large tiles and the rest get compact tiles. The dashboard greets the user by the display name they saved, never by their email address.

## L1-003: Open an app
The system shall open a tile's app in a new browser tab. It shall record when the user last opened the tile and show that on the tile.

## L1-004: Layout editing
The system shall let the user arrange tiles on a grid by moving and resizing them, finish editing, and reset the layout to its default. The layout shall persist.

## L1-005: Quick jump
The system shall let the user search tiles from anywhere with the `/` shortcut and open a match with Enter.

## L1-006: Add from directory
The system shall let the user add an app from a directory of common apps, or add any app by its web address.

## L1-007: Accounts and sessions
The system shall let users sign in by email link with a secure server-side session. Each user shall have a private dashboard, and users shall be able to sign out.

## L1-008: Security and privacy
The system shall validate all input and enforce authorization on every endpoint. A user shall never see or change another user's tiles. The system shall protect against the OWASP Top 10 and use no tracking.

## L1-009: Performance
The system shall respond quickly to dashboard loads and tile changes, with measurable targets.

## L1-010: Responsive and accessible UI
Every screen shall work from phone to desktop (XS through XL), support light and dark themes, and meet WCAG 2.2 AA.

## L1-011: Operability
The system shall log requests, return RFC 7807 problem details for errors, and provide CLI commands to migrate, seed and reset the database. Migrations shall never run on API startup.

## L1-012: Identity provider
The system shall be the OpenID Connect identity provider for the apps its owner publishes, so people sign in to those apps with their ingresso account.
