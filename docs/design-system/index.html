Components

Actions

ButtonButtons trigger actions: add an app, save, delete.Button groupA set of related buttons joined into one control.LinkLinks go somewhere: another page or an app in a new tab.MenuA dropdown of actions opened from a button, such as the account menu.

Inputs

Text fieldA single-line text input with a label, such as an app name or address.TextareaA multi-line text input for longer descriptions.SelectA native dropdown for choosing one option.CheckboxChoose zero or more options.Radio groupChoose exactly one of a few options.SwitchAn on/off setting that applies immediately.Form fieldThe wrapper that stacks label, control, help and error.Form layoutHow fields, summary and actions are arranged in a form.

Navigation

App headerThe sticky bar with the logo, search and actions.TabsSwitch between related views of one page.BreadcrumbShows where the page sits in the hierarchy.PaginationMove between pages of a long list.Skip linkThe first focusable element; jumps past the header to the content.

Containers

CardA bordered surface that groups related content.DialogA modal panel for forms and confirmations.TooltipA short label that appears on hover and focus.DividerA hairline that separates groups.Layout primitivesContainer, grid, stack and cluster: the spacing and alignment helpers.

Data display

TableTabular data with sorting and row actions.ListA vertical list of items with a title and meta line.Description listKey-value pairs.AvatarA circle with a person's initials.BadgeA short status label with a dot.ChipA pill for filters or removable values.

Feedback

ToastA short message that confirms an action and fades away.AlertA message inside the page: inline or as a page-wide banner.Inline messageField help and field errors.Progress barShows how far a task has got.SpinnerAn indeterminate busy indicator.SkeletonA placeholder that matches the final layout while content loads.Empty stateExplains why a view is empty and offers one next step.Error pageFull-page status for 404, 403, 500 and offline.

How to use

  1. Link tokens/tokens.css, then assets/components.css.
  2. Use the class names shown on each component page; never write a colour, size or duration that is not a token.
  3. Engineering consumes tokens/tokens.json (DTCG) for platform constants. Regenerate it after any token change.
  4. The Angular library (frontend/projects/components, ig-*) mirrors these components and keeps the BEM names.
