Feedback and loading

Which feedback for which action, and how to show waiting.

WCAG 2.2 AAStatus: stable
  • Overview
  • When to use
  • Structure
  • States
  • Responsive behaviour
  • Accessibility
  • Content
  • Do and don't
  • Sources

Overview

Match the feedback to the weight of the event: inline for fields, a toast for a completed action, a banner for a lasting state, a dialog only when a decision is needed.

When to use

EventUse
Field is wrongInline message
Tile added, removed, savedToast (with Undo if reversible)
Offline, session endingBanner
Load failedAlert with Try again
Page loadingSkeleton matching the layout
Button action in flightBusy button

Structure

Slack removed
The tile is gone from your dashboard.
Live composed example

States

StateBehaviour
LoadingSkeletons; hidden status "Loading apps…"
ErrorAlert in place of content; chrome stays
OptimisticApply at once, show Undo, roll back on failure with a danger toast

Responsive behaviour

Toasts sit at the bottom: full width on phones, stacked on larger screens.

Accessibility

  • Toasts are polite; errors are assertive and persist.
  • Do not move focus for a toast.

Content

  • Past tense for confirmations.
  • Say what failed and what to do.
