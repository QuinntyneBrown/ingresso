Pattern

Forms

Layout, validation timing, summary and submit states for every form.

WCAG 2.2 AAStatus: stable

Overview

Forms are single column with labels above. They validate on blur, re-validate on input once invalid, and on submit show a summary that takes focus.

When to use

  • Use a form in a dialog for add and edit; use a page for sign-in, reset password and settings.
  • Never edit inline in a page: button-triggered editing opens a dialog or navigates.
  • Several addresses of one kind (redirect addresses, sign-out return addresses) go in one textarea, one per line, with help text that says so. An error names the address that is wrong.
  • A value shown once, such as a new client secret, is a read-only monospace Input with a Copy button beside it, under a warning alert that says it won’t be shown again. Copy announces “copied” through a polite status region and the button reads “Copied”.
  • An item in a list with several actions gets one ghost icon Button (more, labelled “Actions for <name>”) that opens a Menu. Destructive items come last, after a divider, in the danger kind. A state such as “Disabled” is a neutral Badge beside the button.
  • An edit dialog is the add dialog with its values filled in, titled “Edit <name>” and saved with “Save changes”. Fields that can’t change after creation are shown as text, not disabled inputs.
  • Deleting something that can’t be restored asks for its name: Delete stays disabled until the typed name matches exactly. Replacing a credential (rotating a secret) asks first and says the old one stops working at once.

States

StateBehaviour
DefaultFocus on the first field (dialog) or the page heading
InvalidSummary on top takes focus; first invalid field flagged with aria-invalid
SubmittingPrimary button busy and disabled; fields read-only; no layout shift
FailedDanger alert at the top of the form; entries preserved
SuccessDialog closes with a toast; pages show a success alert and say what happens next

Responsive behaviour

Single column at every width; actions stack full width under 640px in dialogs (bottom sheet).

Accessibility

  • Every control has a label; errors link by aria-describedby.
  • Summary is role="alert" and each item moves focus to its field.
  • Required is stated in words, not an asterisk alone.

Content

  • Errors say how to fix. "Enter a full address, like app.asana.com".
  • Primary button repeats the verb: "Add app", "Save changes".
