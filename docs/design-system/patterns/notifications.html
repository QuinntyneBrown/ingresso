Notifications

Toast, banner and notification-centre rules.

Overview

Priority decides the container: a toast for something done, a banner for a lasting state, an alert for something to fix.

When to use

PriorityContainerDismissal
Confirm an actionToastAuto after 8 s; pauses on hover and focus
Reversible actionToast with UndoStays for the full timer
Lasting state (offline, session ending)BannerUntil the state ends or the user acts
FailureDanger toast or alertNever auto-dismisses

States

StateBehaviour
SingleOne toast at the bottom
StackedNewest on top; each on its own timer
PersistentBanner above content; announced once

Responsive behaviour

Full width on phones; stacked on larger screens.

Accessibility

  • Polite live region always in the DOM; errors use role="alert".
  • Never move focus to a toast.

Content

  • Title says what happened; text says what next.
