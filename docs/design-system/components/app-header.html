App header

The sticky bar with the logo, search and actions.

WCAG 2.2 AAStatus: stable

Overview

Always present when signed in. Logo links home; search jumps to an app; Edit layout toggles moving and resizing tiles; Add app is the single primary action; the avatar opens the account menu. On auth pages only the logo shows.

Anatomy

  1. LogoLight and dark variants
  2. SearchJump to an app; "/" focuses it
  3. ActionsEdit layout, Add app, account

Sizes

App header has a single size.

States

Composed of Button, Text field and Avatar; see their pages for states.

Responsive behaviour

Under 768px the search wraps onto its own row and button labels are hidden (icons remain). From 768px everything sits on one row.

Theming

App header reads semantic tokens only (listed under Tokens), so it follows the theme without extra CSS. To re-theme it, override its component tokens or the semantic tokens on a [data-theme] ancestor.

Focus

Sticky bar never covers the focused element (scroll padding set to the header height).

Labelling

Search is labelled "Jump to an app"; avatar is "Account menu for Maya Reyes"; Edit layout reports aria-pressed.

Contrast

Header text

Motion

Backdrop blur only; none under reduced motion.

Touch

Actions are 40px; the bar is 64px tall.

Content

  • Button labels hide below 768px; the icon and aria-label remain.
  • The "/" hint is decorative (aria-hidden).
