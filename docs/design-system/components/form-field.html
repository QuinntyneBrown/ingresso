Form field

The wrapper that stacks label, control, help and error.

WCAG 2.2 AAStatus: stable

Overview

Every input lives in a form field. It sets the spacing between label, control and message, and the aria-describedby wiring.

Anatomy

  1. LabelAbove the control
  2. ControlAny input
  3. Help or errorBelow, linked by aria-describedby

Variants

Help and error.

Shown under the name on the tile.
With help
HTML
<div class="field"><label class="field__label" for="ff2">Address</label><input class="input" id="ff2" type="text" value="linear.app" aria-describedby="ff2-m"><span class="field__help" id="ff2-m">Shown under the name on the tile.</span></div>
Enter a full address, like app.asana.com
With error
HTML
<div class="field"><label class="field__label" for="ff3">Address</label><input class="input" id="ff3" type="text" value="asana" aria-invalid="true" aria-describedby="ff3-m"><span class="field__error" id="ff3-m">Enter a full address, like app.asana.com</span></div>

Responsive behaviour

Fluid: the component fills its container and needs no breakpoint of its own. Verified at 360, 768 and 1280px.

Theming

Form field reads semantic tokens only (listed under Tokens), so it follows the theme without extra CSS. To re-theme it, override its component tokens or the semantic tokens on a [data-theme] ancestor.

Accessibility

Role and pattern

Label + control + aria-describedby message.

Keyboard

KeyAction
TabFocus the control; the label is not a tab stop

Focus

On the control.

Labelling

Error text begins with an icon (⚠) and states the fix. A form summary links to each error.

Contrast

Error text
Help text

Motion

None.

Touch

Label and control together are the target.

Content

  • Label above, never beside, on phones.
  • Errors say how to fix, not what is wrong.
