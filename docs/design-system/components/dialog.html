Dialog

A modal panel for forms and confirmations.

Overview

Per the project rule, button-triggered editing always opens a CDK Dialog (DialogShell) or navigates. Dialogs hold add, edit, delete and sign-out. On phones they become bottom sheets.

Anatomy

  1. IconInforms the kind
  2. Title and descriptionaria-labelledby and aria-describedby
  3. BodyForm or message
  4. FooterCancel then primary

Standard and destructive.

Responsive behaviour

Under 640px the dialog is a bottom sheet pinned to the bottom with rounded top corners; from 640px it is a centred panel.

Theming

Dialog reads semantic tokens only (listed under Tokens), so it follows the theme without extra CSS. To re-theme it, override its component tokens or the semantic tokens on a [data-theme] ancestor.

Accessibility

Role and pattern

WAI-ARIA Dialog (Modal): role="dialog" aria-modal="true", labelled and described; the page behind is inert.

Keyboard

KeyAction
Tab / Shift+TabCycles inside the dialog
EscClose (unless busy)
EnterSubmit the form

Focus

Opens on the first field (forms) or the safest button (confirmations); returns to the opener on close.

Labelling

Title names the task; description explains the consequence.

Contrast

Text

Motion

Fades and scales in over --duration-slow.

Touch

Bottom sheet under 640px; footer buttons are 44px.

Content

  • Title is a question for confirmations: "Delete Linear?".
  • Primary button repeats the verb and object.
