Progress bar

Shows how far a task has got.

WCAG 2.2 AAStatus: stable

  • Anatomy
  • Variants

Overview

Not used yet in ingresso. Use for known-length work; use a spinner for unknown, short work.

Anatomy

  1. Track8px
  2. BarAccent fill

Variants

Determinate, indeterminate, success.

Determinate
HTML
<div class="progress" role="progressbar" aria-label="Importing" aria-valuenow="60" aria-valuemin="0" aria-valuemax="100"><div class="progress__bar" style="--value:60%"></div></div>
Indeterminate
HTML
<div class="progress progress--indeterminate" role="progressbar" aria-label="Working"><div class="progress__bar"></div></div>
Success
HTML
<div class="progress progress--success" role="progressbar" aria-label="Done" aria-valuenow="100" aria-valuemin="0" aria-valuemax="100"><div class="progress__bar" style="--value:100%"></div></div>

Sizes

Progress bar has a single size.

States

Progress bars have no interactive states.

Responsive behaviour

Fluid: the component fills its container and needs no breakpoint of its own. Verified at 360, 768 and 1280px.

Theming

Progress bar reads semantic tokens only (listed under Tokens), so it follows the theme without extra CSS. To re-theme it, override its component tokens or the semantic tokens on a [data-theme] ancestor.

Accessibility

Role and pattern

role="progressbar" with aria-valuenow; indeterminate omits it.

Keyboard

KeyAction
—Not focusable

Focus

n/a

Labelling

aria-label names the task.

Contrast

Fill vs track

Motion

Indeterminate cycle uses --duration-shimmer; static under reduced motion.

Touch

None.

Content

  • Say what is progressing.
